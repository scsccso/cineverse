## 0. 一个重要的截图局限,先说在前面

本地 dev 数据库里目前所有电影的 `poster_url`/`backdrop_url` 都是空的(`Verify Movie`、
`E2E Test Movie`、`Dune Part Three`、`Verify Fix` 全部如此),后端按 Phase 2 的约定
返回占位图(`暂无海报`/`暂无背景图` 图标),不是真实海报/剧照。这意味着:

- 所有截图里"看起来空"有一部分原因是**内容缺失**(没有真实图片),不是布局本身的问题——
  换上真实海报/背景图后,视觉重量会自然回来一部分。
- 但下面标记为"结构性"的发现(卡片比例、容器宽度、间距节奏、字号层级)跟有没有图片
  **无关**,换真实图片也不会自动修好,这部分才是这份文档真正的重点。

每一页的分析都会区分这两类,避免把"换张图就好了"的问题当成"要改结构"的问题来处理。

## 2. 选座页沉浸感增强专项方案

这是本次任务里唯一要求给出"具体实现方向"的部分,按你给的三个方向逐条回应。

### 2.1 银幕弧形视觉引导(建议采用)

**现状**:`seat-map.tsx` 第 38-43 行,银幕提示是一条 `h-1.5` 的线性渐变条 + 文字
"银幕 · {hallName}",纯装饰性但形状是一条直线,没有"弧形银幕"的联想。

**建议做法**:

- 用一个内联 SVG 替换这条渐变直线,画一条浅弧线(`<path>` 用二次贝塞尔曲线,弧度
  很浅,不需要真的模拟透视变形),配合一个径向渐变光晕(可以直接复用已有的
  `--glass-highlight` token 的颜色语言,不需要发明新的设计变量)在弧线中点做一个
  柔光光斑,弧线下方居中放 "SCREEN" 字样(大写、宽字距,呼应现有 "银幕" 中文标签
  已经在用的 `tracking-[0.3em]`)。
- 这是纯装饰性 SVG,不携带任何状态、不响应任何交互,不会影响座位数据流(`seats`、
  `selectedSeatIds` 等 prop 完全不用碰)。
- **无障碍**:SVG 加 `aria-hidden="true"`(和现有的渐变条一样,它本来就不承载信息,
  "银幕 · Hall 1" 这行文字才是承载信息的部分,继续保留为可读文本,不放进 SVG 里
  变成图片文字)。
- 预估影响范围:只改 `seat-map.tsx` 里银幕提示那一小块 JSX,不touch `SeatButton`/
  `SeatLegend`/座位数据逻辑。纯样式+装饰性标记改动。

### 2.2 座位透视/景深处理(建议不做,原因如下)

评估结论:**不建议做**,具体原因分三层:

1. **和现有代码明确保护的一个不变量直接冲突**。`seat-map.tsx` 顶部注释写得很清楚:
   "每排共享同一个 `totalColumns` grid-template,即使 COUPLE 座跨两列,列依然要
   在排与排之间垂直对齐"——这是 Phase 3 就定下、Phase 5 靠 `SeatLayoutGenerator`
   的构造过程+专门单测保证的设计承诺(见 `CLAUDE.md` Phase 3)。如果给"越靠后排
   越大"做视觉缩放,最直接的实现方式(`transform: scale()` 应用在每排的容器上)
   会让不同排的座位在视觉上不再垂直对齐——第 5 排的第 5 列座位不会再正对第 1 排
   的第 5 列座位,直接破坏这条被专门测试保护的对齐保证。
2. **CSS transform 不参与布局尺寸计算,会和现有的横向滚动机制打架**。座位图外层是
   `overflow-x-auto`(专门为了防止窄屏上座位被压缩到 44px 以下,见
   `CLAUDE.md` 1.5 节的无障碍记录),`transform: scale()` 只影响绘制,不影响元素在
   布局/滚动宽度计算里占的空间——也就是说放大后的后排座位在视觉上会溢出它在滚动
   容器里"应得"的宽度,要么被裁切,要么需要额外补偿计算每排的 padding,这块补偿
   逻辑本身就有相当的复杂度,而且每次影厅座位数变化(不同 Hall 的 `totalColumns`
   不同)都要重新验证不会裁切。
3. **收益本身很小**。当前影厅规模是 6~10 排(见 `CLAUDE.md` Phase 3 的 MVP 范围),
   真实电影院里前后排之间的视线透视差在这个排数量级下几乎不可感知——真要做出"看得
   出来"的透视效果,缩放比例就得夸张到不像真实比例,反而显得失真,不是"更沉浸"
   而是"更卡通"。

**如果想要"深度感"但不想承担上面的成本**,一个几乎零风险的替代方案:在座位网格
背后加一个纯 CSS 的垂直渐变蒙层(靠近银幕更亮、往后排逐渐变暗,或者反过来模拟
"银幕光"从前方打过来的氛围光),用 `background: linear-gradient(...)` 叠在座位
网格容器背后一层,不改变任何座位的位置/尺寸/对齐,零 a11y 风险,也不需要处理滚动
溢出。如果你想要"深度感"这个方向,建议做这个,而不是真正的透视缩放。

### 2.3 大厅缩略图 / mini-map(确认不做)

同意你的判断——6~10 排 × 10~14 列在一屏内可以完整看到全貌(本次截图里 6 排座位
一次性全部可见,没有需要"先看缩略图再定位"的滚动/分页场景),加 mini-map 属于
过度设计,不需要评估实现方案,直接排除。
